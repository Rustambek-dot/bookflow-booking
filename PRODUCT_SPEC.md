# BookFlow — Online Booking System — Product Specification

## Обзор
**BookFlow** — SaaS для онлайн-записи: салоны, клиники, студии, консультанты. Клиенты бронируют слоты онлайн, бизнес управляет расписанием, персоналом и выручкой.

## Целевая аудитория
Сервисные бизнесы с записью по времени: барбершопы, стоматологии, фитнес-студии, репетиторы, юристы (2–50 сотрудников).

## Бизнес-задача
Убрать телефонную запись и двойные бронирования; дать клиентам самозапись 24/7, бизнесу — загрузку персонала и предоплату через Stripe.

## Роли
1. **Admin** — услуги, персонал, расписания, аналитика, настройки
2. **Staff** — своё расписание, свои брони, отметка visit completed
3. **Customer** — публичная страница записи, личный кабинет, отмена брони

## Ключевые user flows
1. **Клиент бронирует**: /book → выбор услуги → мастера → свободного слота → контакты → (опц. предоплата Stripe) → подтверждение + email
2. **Отмена**: кабинет клиента → Cancel (не позднее чем за N часов) → слот освобождается, уведомления обеим сторонам
3. **Админ управляет**: услуги (цена/длительность) → персонал → рабочие часы → система сама рассчитывает свободные слоты
4. **Напоминания**: cron за 24ч и за 1ч до визита (email; mock-лог без ключей)

## Страницы
- `/` — landing (hero, features, pricing, FAQ)
- `/book` — публичный виджет записи (мультишаговый)
- `/auth/login|register|forgot-password`
- `/dashboard` — сводка дня: брони сегодня, выручка, загрузка
- `/bookings` — все брони, фильтры по статусу/мастеру/дате
- `/services` — CRUD услуг (название, длительность, цена, категория)
- `/staff` — CRUD сотрудников + рабочие часы
- `/customers` — база клиентов, история визитов
- `/analytics` — загрузка по мастерам, выручка, no-show rate
- `/settings` — бизнес-профиль, интеграции (Stripe, Google Calendar), политика отмены

## База данных
services (id, name, duration_min, price, category, active)
staff (id, user_id, name, specialization, color)
staff_schedules (id, staff_id, weekday, start_time, end_time)
bookings (id, service_id, staff_id, customer_id, starts_at, ends_at, status: pending|confirmed|completed|cancelled|no_show, payment_status, amount)
customers (id, name, email, phone, notes)
+ RLS по business_id, индексы на bookings(starts_at, staff_id)

## Расчёт свободных слотов
Серверная функция: рабочие часы мастера − существующие брони − буфер; шаг = длительность услуги. Реализуется в `src/services/availability.service.ts` (чистая функция, покрыта типами).

## Интеграции (все с mock mode)
- **Stripe** — предоплата (Checkout Session); mock: имитация успешной оплаты
- **Google Calendar** — push событий мастеру; mock: лог в консоль + запись в таблицу integrations_log
- **Resend** — подтверждения и напоминания; mock: лог

## Дизайн-система (отлична от Проекта 1)
- Палитра: **teal/emerald** (primary #0d9488, accent #f59e0b), светлый лендинг
- Типографика: заголовки крупнее, стиль «дружелюбный сервис» (в противовес «корпоративному» CRM)
- Карточки с мягкими скруглениями (rounded-xl), пастельные статус-бейджи
